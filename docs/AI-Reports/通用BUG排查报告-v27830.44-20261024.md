## 二、P1（1 条）

### BUG-01【功能坏死 + 功能报错】浏览器 Cookie 导入把钥匙串口令截断到 16 字节，对真实浏览器整体坏死
- **位置**：`src/Features/ResourceDetector/RDBrowserCookieImporter.m:306-307`
- **证据**：`return [data subdataWithRange:NSMakeRange(0, MIN(16, data.length))];`
- **根因**：Chromium 的 macOS `Safe Storage` 口令是随机生成的（普遍 >16 字节），派生规约要求**完整口令**送入 `PBKDF2-HMAC-SHA1("saltysalt", 1003 轮)`。截断后派生密钥必然错误 → 样例试解失败 → 全部候选服务名失败 → 报「密钥均不匹配」→ 导入功能对 Chrome/Edge 等真实浏览器**整体坏死**。
- **为何测试没拦住**：`CookieImportTests.m` 只对解密函数直接喂 16 字节密钥（截断成为恒等操作），截断行本身零覆盖。
- **修复方向**：`return data;`（用完整口令派生，仅加 `length==0` 判空）。一行修复。
- **复核**：已亲自读码确认 ✅

## 三、P2（6 条）

### BUG-02【功能报错】预览环回服务器未屏蔽 SIGPIPE，快速切换预览可致整个 App 崩溃
- **位置**：`src/Features/ResourceDetector/RDPreviewController.m:157-173`（建 socket 无 `SO_NOSIGPIPE`）、`:217`（`send` 无返回值检查）
- **触发**：AVPlayer 在 `send` 前断开连接（典型：用户快速切换预览条目）→ `send` 得 EPIPE → 默认 SIGPIPE 终止进程。这是 App 自管的裸 socket，CFNetwork 内部会自行忽略 SIGPIPE，此路径没有任何防护。
- **修复方向**：建 socket 后 `setsockopt(SOL_SOCKET, SO_NOSIGPIPE)`；容忍 send 失败。

### BUG-03【功能报错/功能坏死】预览环回 accept 循环把单次瞬时失败当永久死亡，且 recv 无超时
- **位置**：`src/Features/ResourceDetector/RDPreviewController.m:178-221`
- **触发**：a) macOS `accept` 返回 `ECONNABORTED`（BSD 真实行为，AVPlayer 快速断开即可触发）→ 循环 break，但 listen fd 仍 open，后续每次 start 都走「已在服务」分支 → **预览清单请求永远挂起，直到 stopPreview 前不自愈**；b) 任意本地进程连上不发包 → `recv` 永久阻塞单线程循环；c) `_loopbackBody/_loopbackPath` 主线程写、环回队列裸读，无同步。
- **修复方向**：`ECONNABORTED/EINTR` continue 其余才 break；conn 设 `SO_RCVTIMEO`；共享状态经队列或原子快照。

### BUG-04【功能报错】RDAdaptiveTransport 的 `_activeHopper` 是单槽共享状态，并发取消会杀死另一条请求的 curl
- **位置**：`src/App/RDAdaptiveTransport.m:94-96, 69-74`
- **触发**：元数据服务允许 4 个 work 并发；两个 work 同时命中指纹拦截进入 curl 回退时，后者覆写 `_activeHopper`；此后取消请求 A 实际终止的是请求 B 正在跑的 curl（取消语义串号）。另：完成后从不清空，长期持有已结束 hopper。
- **修复方向**：hopper 归属到请求（composite token 持有弱引用），或按请求登记/注销的集合。

### BUG-05【功能报错】previewOnly 预热把「从未探测」的字段写成 Unknown 落缓存，30 秒内点击详情显示假「未知」
- **位置**：`src/Features/ResourceDetector/RDMetadataService.m:650-657`（finish 收尾）+ `:233-234`（storeField 放行 Unknown）+ `:314-322`（早退分支）
- **触发**：列表预热过的行（有海报）在缩略图落地后 30 秒内被点击：finish 把 duration/size/dimensions 三个从未开跑的 Loading 字段映射为 Unknown 并落缓存（TTL 30s）→ 点击后从缓存恢复 Unknown → `anyLoading=NO` 早退，不再发起媒体腿。用户看到的是失真的「未知」而非真实探测结论。违背头注释「失败/超时不写入缓存——下次订阅必须重试」的设计意图。
- **修复方向**：previewOnly 收尾时对未探测字段跳过 storeField。

### BUG-06【功能报错】curl 逐跳传输对未知长度响应无任何字节上限：磁盘可被写满
- **位置**：`src/Shared/Infrastructure/RDCurlHopper.m:164-166`（`--max-filesize` 在尺寸未知时不生效）、`:241-251`（先全量落盘再全量进内存，之后才检查 budget）
- **触发**：恶意/异常站点对元数据探测返回 chunked 超大响应 → curl 先写满 /tmp，再读满内存。同项目 `HTTPClient.m:302-313` 与 `RDMetadataTransport.m:300` 都有流式限流，唯独 curl 回退腿是「事后诸葛」式检查。
- **修复方向**：用 `-r 0-(budget-1)` Range 上限（与探测语义一致），或监控临时文件大小超限即 terminate。

### BUG-07【功能性缺失】批量探测发现的元数据历史永不落盘，重启后标题/封面退化
- **位置**：`src/App/ResourceDetectorApp.m:3093`（批量聚合全程 `applyMediaList:final:NO`）+ `:3114-3127`（`batchFinish` 无 persist）
- **根因**：`applyMediaList` 只在 `final:YES` 时调 `[self.metadataRecovery persist]`；批量模式所有批次都是 final:NO，`batchFinish` 只更新文案。批量探测记录的标题/封面（第 38 轮防退化机制的输入）跨会话全部丢失。
- **修复方向**：`batchFinish` 里补一次 `[self.metadataRecovery persist]`。

## 五、测试失败项根因（均非产品代码缺陷）

### download-integrity（T57 断言）——测试自身缺陷（flaky）
- 首跑：`FAIL: T57: 放弃删除后文件描述符已关闭（不泄漏 fd）`；**同套件重跑全绿（exit=0）** → 非确定性。
- 复核：产品代码 `quarantineAndRemoveOwnedTempDirectoryAtPath` 的「统一出口」无条件执行 `releaseTempDirClaimForPath`（close fd），改名失败路径同样覆盖；断言用 `fcntl(F_GETFD)` 检查已关闭的 fd **编号**，而 close 与断言之间隔着多次 NSFileManager 调用（FileExists 等），BSD 会把新 open 分配到刚释放的最小编号 → 断言受 fd 编号复用干扰，天然 flaky。
- **结论：产品无 fd 泄漏；建议测试改为快照进程级 fd 计数（/dev/fd 或 proc_pidinfo）而非单点 F_GETFD。**

### preview-playback——测试环境缺依赖
- `tests/fixtures/preview/make-fixtures.sh:21` 需要一个**带 hls muxer 的完整版 ffmpeg** 来生成测试夹具；本机未安装完整版 ffmpeg（`which ffmpeg` 无）→ 套件失败。
- **产品不受影响**：生产 HLS 合流链路是「hls **demuxer** 读本地 m3u8 → `-c copy` → `-f mp4` 输出」（`RDStreamDownloadTask.m:142`），实测内嵌 ffmpeg 8.0 具备 hls demuxer 与 mp4/mpegts/adts muxer，链路完整。
- 附带发现：该套件在这台机器上从未真正跑过真实播放集成部分，属测试环境债。
