2026-11-10。执行者串行完成，交 Lead 读源码与原始证据审查；不声称 Lead 亲自复跑。仅 TLS 默认策略、隔离测试和本计划/报告，**curl / 认证不在本批次施工范围**。未完整构建、安装或发布。

## 结果与行为变化

- [生产头](<src/Shared/Infrastructure/RDTLSTrust.h>)：现有键 `SevenZZKeyAllowRevokedCertificate` 未配置时不再默认开启吊销容错，改为严格系统信任。已有显式 YES 仍保留窄容错，显式 NO 仍严格。
- 新增纯值入口 `RDTLSAllowRevokedCertificateForValue`：NSNumber 1 或字符串 YES / true / 1（忽略大小写）才明确允许；缺失、其它数值、空白前缀和畸形类型均不允许。没有写偏好、迁移既有值或增加配置 UI。
- 新增显式许可评估入口 `RDTLSEvaluateServerTrustWithRevocationAllowed`，真实原接口仍读取原键并调用同一评估函数。可信 SecTrust 继续交系统默认；不可信且未许可即拒绝。既有 SAN DNS-only、通配边界、仅 leaf、唯一失败项、出错索引及中文/英文索引解析逻辑均未改。
- 保留 [源 Info.plist](<src/Packaging/Info.plist>) 的 ATS 例外；没有声称一次原生默认值改动统一了 curl 的 TLS 策略。
- **兼容成本明确接受**：此前未设置该键的用户会由容错转严格，依赖已吊销证书兼容的站点可能失败；显式 YES 用户仍须满足所有窄容错门，不是忽略全部证书错误。
- 不改变 App 页面文字、控件、布局、颜色、入口或弹窗，不启动 App / 浏览器 / 窗口。

## 隔离方式与断言变化

[TLSTrustTests](<tests/Tests/TLSTrustTests.m>) 原开关测试直接读写 standardUserDefaults，本批次移除该副作用，改为直接注入内存值。原“缺失配置默认开启”改为“缺失配置默认严格”是 Lead 明确批准的更严格规格，不是删弱拒绝断言；原显式 YES/NO 和全部 SAN / leaf / index 断言保留。

新增 [默认 wrapper 测试](<tests/Tests/TLSDefaultPolicyTests.m>) 仅在测试编译单元替换 NSUserDefaults 读取边界，直接运行真实生产默认 wrapper：不复制默认策略，不触用户偏好。新增 [吊销评估集成测试](<tests/Tests/TLSRevocationIntegrationTests.m>) 只替换 Security 框架边界，真实生产评估器串起许可、唯一 leaf/index 与 SAN 门。它是边界夹具，**不是在线 OCSP 或真实被吊销链端到端**。

离线真实 SecTrust 使用 [本地证书配置](<tests/fixtures/tls-trust.cnf>)，由系统 openssl 在证据目录生成一次性自签证书，关闭网络取证。可信场景仅对当前 SecTrust 对象显式设置局部测试锚，不改钥匙串/系统信任；另测无锚自签、域名不符、校验时刻已过期，在严格与显式许可两档均符合预期。测试没有生成真实吊销/OCSP 环境，也不冒充系统全局已信任的公共证书。

[套件入口](<tests/Tests/tls-trust.sh>) 支持独立 `RD_TLS_OUT` 和隔离副本 `RD_TLS_HEADER_DIR`，每份编译/运行日志单独保留。在线站点是未选定的另一套件，改用 NOTE 明确范围，不用 SKIP 把已选离线套件误标不完整；本套件三段均给结构化 PASS，失败不被跳过标记覆盖。
