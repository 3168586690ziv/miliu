## 分阶段计划

### 第 1 阶段（当前授权）：三个确认缺陷与生产逻辑回归

A. 修复 RDPreviewPlayPinned 创建网络任务但未 resume：新增直接覆盖生产控制器编排、使用网络/窗口替身的无 GUI 守卫。

B. 修复 WAL 尾行损坏后继续追加导致新记录丢失：覆盖恢复后追加再恢复，保护原有有效记录；明确 UTF-8 损坏、完整但无换行记录、重复打开、压缩顺序语义。仅使用独立临时目录。

C. 统一预览来源头策略（已批准方案①）：原生终跳解析与 master 请求用现有媒体净化及逐跳重定向净化；AVPlayer 的 Origin/CrossOrigin 仅来源 origin，None/FullPath 不主动注入 Referer。资产级固定头无法证明未知子请求同源，因此不注入完整路径/query。依赖完整 Referer 的预览可能不可用，下载链路不变，不在 UI 增加说明。测试覆盖三个入口四档、同跨域、query/fragment/userinfo 和重定向剥离后不回流；不虚称已覆盖系统自生请求头或 HLS 子资源 DNS 防护。

**验收**：先新增测试在原代码确实变红，再修复变绿；记录命令原文、退出码、关键输出、编译告警；测试直接覆盖生产逻辑，不复制等价算法。最终提交 diff/status 与阶段报告供 Lead 判断。

**预期写范围**：RDPreviewController.m、RDQueueWAL.m、必要但尽量不改既有链路语义的 HTTPPrivacyPolicy 接口、对应测试源/脚本、本计划与阶段报告。需要改 ResourceDetectorApp.m、设置页或版本文件时停止并报告。

- AVPlayer 固定资产级请求头与任意跨域 HLS/重定向间的隐私边界不能靠修改初始头就保证：必要时先交方案。
- WAL 修尾不能破坏历史完整记录；不得以全文 UTF-8 解码失败当作整文件为空。
- 聚焦生产守卫不创建窗口/真实播放器；第三阶段新增的明确 E2E 授权允许无窗口、静音的真实 AVPlayer 访问固定本机夹具，普通 guard 仍保持纯边界替身。所有路径均不启动主 App、不抢前台。
