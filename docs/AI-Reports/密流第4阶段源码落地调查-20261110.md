### 建议直接实施的最小闭环

1. 新增纯逻辑内存 `RDMediaAuthContext` 和可注入 snapshot provider。provider 只在一次用户发起下载时取快照，异步完成用 jobID + generation + context 身份守卫；未准备好不能先匿名启动再悄悄换身份。取消/换代清理旧准备状态，重试重新获取，不把快照写 WAL/Store/偏好/日志。
2. 生产 provider 可在 App 初始化接线到 WebKit 的 cookie API，Feature 层不依赖 WebKit。只允许来源页和实际请求同源（scheme + host + effective port），domain 边界/path 匹配/Secure/有效期/host-only 一并筛选。不猜 partitioned cookie 的分区信息；系统 API 不足以证明归属时不自动外推。没有来源、跨域 CDN、无上下文均匿名。HttpOnly 不等于禁止 HTTP 发送，但不得进入页面 JS 或日志。
3. 上下文绑定到单次 job，manager 交给 probe 与 stream；每个请求目标确定后应用，不能把完整 jar 复制到固定模板。能力探测、直链、分段、fresh reissue、HLS/DASH 所有 fetch 都使用同一纯筛选方法。
4. **建议本轮认证最小版：携带认证上下文的请求禁用 curl 回退；匿名请求维持原行为。** 这样不会把 Cookie/Authorization 放进 argv，也不在回退中恢复被 native redirect 剥掉的凭据。不能称“完整认证 curl 已支持”，但 native 下载闭环可单独验收。
5. 如要求认证 curl 也可用，必须另做：逐跳有效请求净化；凭据经内存 stdin 配置（不是 argv/临时文件）；响应头以内存 pipe 解析（防 Set-Cookie 落盘）；取消与 stderr 错误不泄露值；native 跳转后的最终认证状态必须传回包装腿。范围大于小补丁，建议分开验收。
6. 不给 AVPlayer 资产固定头注入 Cookie/Authorization。认证预览仍未解决；其子请求/重定向不受上述 native 上下文约束。

## B. 翻译：默认本地，外发需显式技术配置

真实创建点：[协调器初始化](<src/App/RDMetadataRecoveryCoordinator.m#L58-L68>)。真实结果合同：[resolvedTitleFor](<src/App/RDMetadataRecoveryCoordinator.m#L159-L171>) 在译文为空时保留原题；因此翻译器在本地无可用映射时仍返回空串，不要返回未经验证的“译文”来改变统计。现有 [离线词表](<src/Features/ResourceDetector/ResourceTitleTranslator.m#L196-L264>) 可直接复用。

最小方案：在 [翻译器头](<src/Features/ResourceDetector/ResourceTitleTranslator.h>) 增加可注入网络许可初始化参数；默认 NO。保持原初始化兼容但默认本地；显式技术配置可由协调器读取一个文档化环境值（仅 `=1` 启用）并传入，不读写用户偏好，不加 UI。入口未许可先走离线字典，不创建请求；有许可再走现有 [第三方 GET](<src/Features/ResourceDetector/ResourceTitleTranslator.m#L279-L306>)。只改 GET 为 POST 不能解决标题外发。

需要同时补生命周期：当前 [cancelAll](<src/Features/ResourceDetector/ResourceTitleTranslator.m#L407-L409>) 只 invalidateAndCancel，**没有置 `_session=nil`**，与文件前面“取消后惰性重建”的注释不符；现有 session getter 只在 nil 时重建。源码也未见集中去重/缓存，不要假称已有。建议每代 operation 表按 normalized source + permission 去重，main-thread owner；cancel 先失效 generation、清空 callbacks 并异步以空结果完成一次，再取消会话并置 nil；晚到回调不再完成/启动分段请求。若不做去重则明确不承诺，不需顺手引入跨运行持久缓存。

测试清单：新增 translator privacy tests 用 NSURLProtocol 捕获，默认零请求、本地命中/无命中/中文、显式允许准确请求、许可关闭后的晚到、重复请求合并、取消后可再次请求、所有 completion 主线程且一次。保留 [MetadataRecoveryTests](<tests/Tests/MetadataRecoveryTests.m>) / [metadata-recovery.sh](<tests/Tests/metadata-recovery.sh>) 的原题回退与协调器接线断言；不运行真实外网。

## C. TLS：缺省严格，保留显式窄容错

真实缺省点只有 [RDTLSAllowRevokedCertificateEnabled](<src/Shared/Infrastructure/RDTLSTrust.h#L46-L61>)。将缺失配置从 YES 改 NO，保留显式 YES/NO；同步注释，不改 SAN、出错证书索引和唯一 leaf revocation 判据。[统一评估](<src/Shared/Infrastructure/RDTLSTrust.h#L307-L335>) 仍先系统信任，严格关闭只对不可信证书拒绝。

避免测试动标准用户偏好：抽出接受 `NSUserDefaults *` 的开关读取纯接口或接受配置值的纯函数；测试用独立 suite/内存配置。当前 [TLS switch tests](<tests/Tests/TLSTrustTests.m#L163-L174>) 直接改 standardUserDefaults，不能照旧执行后声称完全隔离。改成隔离配置后保留显式开关断言，仅把默认开启的旧规格改为默认严格，并记录此规格变更不是删弱安全断言。中文/英文索引、leaf vs intermediate、SAN DNS-only/通配边界等原断言全保留；本地证书夹具可测系统正常信任/自签拒绝/域名不匹配/过期。

header-only 改动会影响下载、probe、preview、静态探测、元数据与封面恢复消费者，不需要新链接对象；所有相关调用应重新编译。优先 [tls-trust.sh](<tests/Tests/tls-trust.sh>)、[redirect-policy.sh](<tests/Tests/redirect-policy.sh>)、[stage12-regression.sh](<tests/Tests/stage12-regression.sh>)、[metadata-recovery.sh](<tests/Tests/metadata-recovery.sh>) 及仅编译静态探测/元数据消费者。在线 [tls-trust-real-site.sh](<tests/Tests/tls-trust-real-site.sh>) 不在本任务授权/环境内。

保留 [Info.plist](<src/Packaging/Info.plist>) 的 ATS 例外，不把默认严格误称为收回 ATS 例外；显式曾开启容错的用户依旧可走窄分支，未设值用户会改变行为。curl 自身 TLS 策略与该 header-only 原生分支不等价，不声称一次默认值改动统一了所有传输栈。
