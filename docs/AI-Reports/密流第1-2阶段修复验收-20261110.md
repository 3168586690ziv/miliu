## 生产改动（仅三个 .m）

### 1. [RDPreviewController.m](src/Features/ResourceDetector/RDPreviewController.m)

**A：** 创建钉选 master 任务后保存并 resume 一次；从公开 start 入口走真实资格判定及生产编排，不复制算法。

**C：已批准的方案①：**

- 终跳解析和 master 初始请求调用现有媒体 Referer 净化。
- 原生重定向保存每个任务的“当前有效上一跳”，调用现有重定向净化；Cookie / Authorization / FullPath Referer 一旦被剥掉，回到原站也不从 originalRequest 恢复。
- AVPlayer 资产：Origin / CrossOrigin 最多来源 origin；None / FullPath 不主动注入 Referer。无 path、query、fragment、userinfo，也不 raw-fallback。
- URLPolicy 的初始、原生重定向、终跳及改写后的远程 URL 校验保留；安全策略明确拒绝不通过“回退原始 URL”绕开。
- 不修改 [HTTPPrivacyPolicy.m](src/Shared/Infrastructure/HTTPPrivacyPolicy.m) 其它消费者的历史语义，也不引入媒体代理。

**第 2 阶段：**

- 终跳解析改为 completion + 主线程回调；删除生产路径的信号量等待。8 秒请求超时与 9 秒异步 watchdog 保留有界 fallback，但用户点击不再等待网络。
- start / stop 使用递增 generation，跟踪 resolver / master 任务与上下文；换媒体、关闭时取消在途任务，取消前先失效/清理旧状态，兼容同步取消回调和取消中重入 start。
- 完成回调以 generation + 请求上下文身份双重判断；旧成功/失败、旧 KVO、旧超时和旧环回清理不能重新播放、显示旧错误或关闭新代资源。
- 同步 transport completion 也先排到主线程队列，不在 start 栈内装配播放；创建任务期间重入 stop 会取消任务而不 resume。
- pending 阶段计为预览 active，使画质切换可以取消旧准备流程。来源页做快照，避免媒体对象后来被原位修改影响异步资产头。
- 环回服务器首次启动显式保存正文；每代固定自己的 body/path/监听 FD，工作队列唯一关闭 FD，原子取消标记配合短 poll/recv 等待退出，不跨线程关闭后重用全局 FD。HTTP 实测包含真实停服与旧清理迟到，不只有替身测试。

### 2. [RDQueueWAL.m](src/Features/ResourceDownload/RDQueueWAL.m)

保留并复核交接 A/B 中的 B 修复：逐行按字节解码，损坏 UTF-8 行不抹掉此前有效历史；追加前修复非法未终止尾部、为完整无 LF 记录补分隔符；恢复、追加、压缩同 IO 队列串行；读取失败不覆盖日志。覆盖中间坏行、长尾跨块、终态无换行、压缩进度、顺序重复打开。未承诺多进程/多实例同时写同一 WAL 的锁保护。

### 3. [RDFailureDiagnosis.m](src/Features/ResourceDownload/RDFailureDiagnosis.m)
